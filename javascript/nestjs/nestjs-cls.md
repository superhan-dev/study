# NestJS CLS란?

NestJS를 사용하면서 로깅 시스템에 관심을 가지다보니 자연스레 NestJS CLS를 접하게 되었다.

nestjs-cls는 NestJS용 AsyncLocalStorage 래퍼 라이브러리다. 자연스럽게 생기는 꼬리질문.. AsyncLocalStorage는 무엇인가?

## AsyncLocalStorage란?

Node.js 16.4에서 정식 추가된 API로 비동기 호출 간에 상태를 저장하고 공유할 수 있도록 도와주는 기능이다.
쉽게 표현하면 Java에서는 각 Thread 마다 독립적인 context를 유지할 수 있도록 ThreadLocal이라는 기능을 제공하지만 NodeJS 에서는 SingleThreaded Event Loop 기반의 비동기 실행 모델을 사용하기 때문에 여러 실행 흐름 간의 context를 관리하는 방식이 달라져서 ThreadLocal과 같은 기능을 직접 구현하기 어려운 점이 있다.

때문에 비동기환경에서 쓰레드 한정적으로 로컬스토리지의 필요가 생겼기 때문에 만들어진 저장소이다.

### 왜 ThreadLocal 공간이 필요한가?

ThreadLocal이 필요한 이유는, 각 요청마다 다른 값을 “전역처럼” 어디서나 쓰고 싶은데, 진짜 전역 변수로 두면 여러 요청/쓰레드가 서로 값을 덮어써서 동시성 문제가 생기기 때문이다.

그래서 각 쓰레드마다 별도의 “로컬 저장소”를 하나씩 주고, 그 저장소에 traceId, 현재 사용자 정보, tenantId 같은 값을 넣어두고 요청 처리 흐름 전체에서 꺼내 쓸 수 있게 해주는 개념이 ThreadLocal이다.

브라우저 쪽으로 비유하면, 모든 탭에서 공유되는 전역 변수 대신 각 탭마다 따로 갖고 있는 저장소(sessionStorage 같은 것)를 두는 느낌으로 이해할 수 있다. 서버에서는 그 “탭” 역할을 쓰레드나 요청 컨텍스트가 맡는 셈이다.

### 언제 사용할 수 있는가?

요청마다 하나의 TraceID를 발급하고 전역에서 로그를 찍을 때 공유하고 싶다고 가정해보자. 이런 상황에서 서버에서도 브라우저의 로컬스토리지 같은 공간이 있다면 편하게 공유해서 사용할 수 있게 된다.
