쿠버네티스(Kubernetes)에서 서비스 타입(NodePort, ClusterIP, LoadBalancer)과 인그레스, 트래픽 흐름, 파드/디플로이먼트/레플리카셋의 관계를 실무적으로 설명하시오.

• 쿠버네티스에서 인그레스 컨트롤러가 동작하는 방식과, L7(HTTP) 기반 라우팅의 내부 처리 흐름을 설명하시오.

- 쿠버네티스에서 인그레스 컨트롤러는 외부 트레픽을 HTTP 기준으로 해석하여 인그레스 리소스에 정의된 Host/Path 규칙에 따라 내부 서비스로 라우팅하는 역할을 합니다.

인그레스 컨트롤러에는 Nginx ingress controller와 alb ingress controller가 있는데 Nginx Ingress Controller는 외부 LB에서 로드밸런싱된 트래픽을 받아 사용자가 커스텀한 방식으로 헤더, 쿠키, 라우터 정보를 읽어 보다 유연하게 처리할 수 있고 ALB Ingress Controller를 사용할때는 AWS에서 기본적으로 제공하는 LB에 따라 트레픽이 유입됩니다.

트래픽이 Service로 들어오면 kube-proxy라는 L4 로드벨렁싱 방식으로 Pod 엔드포인트에 분산됩니다.

• 서비스 디스커버리와 DNS 레코드 생성, 클러스터 내부 통신
(ClusterIP)과 외부 노출(NodePort, LoadBalancer)의 차이점은?

LoadBalancer를 가지고 서비스를 생성하게 되면 외부 LB가 생성되고 해당 LB에 연결된 인그레스는 외부에서 들어오는 트래픽을 서비스로 전달할 수 있게 된다.

이런 구조에서는 서비스가 L4 스위치 역할까지 하게 되는 구조가 된다.

서비스는 L4 장치와 같은 역할을 한다.

- 근데 LoadBalancer로 되어있는 pod가 로드벨런싱을 하는것 아닌가?
- 그렇다면 ClusterIP로 설정되어 생성된 pod는 내부 통신이 가능한 것이고 NodePort를 사용하면 외부 LB와 직접통신이 가능한 Pod를 생성하는 설정인데 LoadBalancer는 뭐지?

클러스터 영역안에서 외부에 노출되는 pod가 있고 내부적으로만 통신하는 설정을 ClusterIP 라고 한다. 말그대로 내부에서만 통신이 가능하며 외부와 통신을 원할 시 Nginx Ingress Controller와 같이 L7스위치 통신할 수 있는 외부 통신용 Pod가 있어야 외부와 통신이 가능하다.
