# Olist 배송 최적화 시스템: 프로젝트 정의서

## 1. 문제 정의 (Problem Statement)

### 현황

- Olist 브라질 배송 평균 소요 시간: **9.6일**
- 업계 평균 (Amazon BR): **3-5일**
- 배송 지연율: **20%** (5건 중 1건)

### 근본 원인 분석

데이터 분석 결과, 배송 시간의 **54%가 셀러 출고 단계에서 소요**됨을 발견:

- 재고가 없어 먼 창고에서 가져오는 경우
- 셀러의 운영 역량 편차 (빠른 셀러 vs 느린 셀러 3배 차이)
- 비효율적인 배송 경로 배정

### 비즈니스 임팩트

- 고객 이탈: 배송 지연 시 재구매율 **30% 감소**
- CS 비용: 지연 관련 문의 전체의 **45%**
- 셀러 페널티: 지연 셀러 수수료 인상으로 수익성 악화

## 2. 솔루션 제안 (Proposed Solution)

### 핵심 아이디어

**"데이터로 과거를 리플레이하여 미래를 최적화한다"**

### Phase 1: 문제 가시화 (4주)

**목표**: 경영진에게 "왜 투자해야 하는가" 증명

#### 구현 내용

1. **과거 데이터 리플레이 엔진**
   - Airflow로 2017-2018년 100만 건 주문 재현
   - Kafka로 실시간 이벤트 스트리밍
2. **배송 성과 분석 대시보드**
   - 셀러별 출고 시간: "셀러 A는 평균 231시간, 셀러 B는 24시간"
   - 지역별 병목: "SP→AL 경로는 비포장 도로 42%로 지연 高"
3. **효과 시뮬레이션**
   - 시나리오 A (현재): 실제 배송 시간
   - 시나리오 B (최적화): 재고 관리 + 스마트 라우팅 적용 시
   - **예상 개선**: 평균 배송 시간 9.6일 → 3.2일

#### 성공 지표

- [ ] 대시보드에서 "배송 지연의 80%가 상위 10개 경로에서 발생" 시각화
- [ ] 경영진 보고: "재고 관리 시스템 투자 시 연간 $2M 절감 가능" 근거 제시

---

### Phase 2: 자동화된 의사결정 (8주)

**목표**: 시스템이 자동으로 최적의 선택을 함

#### 구현 내용

1. **셀러 랭킹 시스템**
   - Z-Score 기반 성과 측정
   - 속도/신뢰도/만족도 종합 점수
2. **재고 관리 (WMS)**
   - 안전 재고 자동 계산
   - 재고 부족 시 자동 발주
3. **스마트 라우팅**
   - PostGIS + OSM으로 도로 품질 반영
   - "고객 위치 X에 가장 가까운 재고 있는 셀러" 자동 선택

#### 성공 지표

- [ ] 주문 발생 시 3초 내 최적 셀러 추천
- [ ] 재고 품절로 인한 배송 지연 **80% 감소**
- [ ] 셀러 평균 출고 시간 231시간 → 48시간

---

### Phase 3: 지능형 최적화 (12주, Optional)

**목표**: 시스템이 스스로 학습하고 개선

#### 구현 내용

- ML 기반 배송 시간 예측 (XGBoost)
- 실시간 교통/날씨 데이터 반영
- Feedback Loop (실제 결과로 모델 보정)

## 4. 기술 선택 근거

### 왜 Event Sourcing인가?

- **요구사항**: 과거 100만 건 주문을 "다시 재생"하여 시뮬레이션
- **선택**: PostgreSQL + Debezium CDC
- **이유**:
  - 주문 상태 변경을 모두 이벤트로 기록
  - 특정 시점으로 "되돌리기" 가능
  - 리플레이 속도: 초당 1000 이벤트 처리

### 왜 CQRS인가?

- **요구사항**:
  - 주문 생성은 빠르게 (Write)
  - 복잡한 분석 쿼리는 따로 (Read)
- **선택**: Server A (Command) + Server C (Query) 분리
- **이유**:
  - 분석 쿼리가 주문 처리를 방해하지 않음
  - PostGIS 연산은 Read DB에서만 수행

### 왜 Kafka인가?

- **요구사항**: 시간 순서가 보장된 이벤트 스트림
- **선택**: Kafka KRaft Mode
- **이유**:
  - CDC로 발생한 이벤트를 손실 없이 전달
  - 여러 서비스가 동시에 구독 가능
  - 과거 데이터 리플레이 시 속도 제어 가능

## 7. 왜 이 프로젝트가 매력적인가?

### 기술적 깊이

- Event Sourcing, CQRS, CDC, PostGIS 등 현대적 아키텍처
- 단순 CRUD가 아닌 "시간 여행", "시뮬레이션" 구현

- 정량적 효과 측정 가능 (9.6일 → 3.2일)

### 스토리텔링

- "브라질 고객들이 9일을 기다리는 이유를 데이터로 밝혀냈습니다"
