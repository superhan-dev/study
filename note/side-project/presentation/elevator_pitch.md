## 2분 버전 (기술 블로그)

### 문제
브라질 이커머스 Olist의 고객들은 평균 **9.6일**을 기다립니다.
Amazon Brazil(3-5일)의 2배입니다.

### 발견
100만 건의 주문 데이터를 분석한 결과:
- 배송 시간의 **54%가 셀러 출고 단계**에서 소요
- 상위 10% 셀러는 24시간, 하위 10%는 231시간 소요
- 재고가 없어 먼 창고에서 가져오는 경우가 주요 원인

### 해결책
**"과거 데이터를 리플레이하여 최적 시나리오를 시뮬레이션"**

1. **Event Sourcing**: 100만 건 주문을 Kafka로 스트리밍
2. **CQRS**: 분석 쿼리를 별도 DB에서 실행 (PostGIS)
3. **시뮬레이션**: "만약 재고 관리 시스템이 있었다면?" 계산

### 결과
| 지표 | Before | After | 개선 |
|------|--------|-------|------|
| 평균 배송 시간 | 9.6일 | 3.2일 | **-67%** |
| 셀러 출고 시간 | 231시간 | 48시간 | **-79%** |

### 기술 스택
- **데이터**: PostgreSQL + PostGIS (지리 분석)
- **스트리밍**: Kafka + Debezium (CDC)
- **시각화**: Grafana (실시간 대시보드)
- **시뮬레이션**: Python + Pandas

---

### Slide 2: 데이터 분석
![차트: 배송 단계별 소요 시간]
```
주문 생성 → 결제 승인:    0.5일 ( 5%)
결제 승인 → 셀러 출고:    5.2일 (54%) ← 병목!
셀러 출고 → 고객 도착:    3.9일 (41%)
```

**SQL 쿼리로 증명:**
```sql
SELECT 
  AVG(carrier_date - approved_at) AS prep_time,
  AVG(customer_date - carrier_date) AS shipping_time,
  AVG(customer_date - approved_at) AS total_time
FROM olist_orders_dataset;

-- 결과: prep_time = 5.2일 (전체의 54%)
```

---

### Slide 3: 근본 원인
![테이블: 셀러별 성과]
```
셀러 A (SP):  24시간 출고, 재고 있음
셀러 B (AM): 231시간 출고, 재고 없어 먼 창고에서 가져옴
```

**문제:**
- 재고 관리 시스템 부재
- 주문을 "가까운 재고 있는 셀러"에게 자동 배정하지 못함

---

### Slide 4: 해결책 - 시뮬레이션
**"만약 시스템이 자동으로 최적 셀러를 선택했다면?"**

```python
# Scenario A (실제)
order → seller_B (231시간, 재고 없음) → 9.6일

# Scenario B (최적)
order → seller_A (24시간, 재고 있음) → 3.2일

savings = 6.4일 (67% 개선)
```

**10만 건 시뮬레이션 결과:**
- 평균 단축: 6.4일
- 총 절감 시간: 640,000일
- CS 문의 감소: 45% → 18%

---

### Slide 5: 기술 아키텍처
![다이어그램: Event-Driven Architecture]
```
Airflow (데이터 리플레이)
  ↓
PostgreSQL (Event Store)
  ↓ CDC (Debezium)
Kafka (이벤트 스트림)
  ↓
Server C (PostGIS 분석)
  ↓
Grafana (실시간 대시보드)
```

**왜 이 구조인가?**
- Event Sourcing: 과거 데이터를 "다시 재생"
- CQRS: 분석이 주문 처리를 방해하지 않음
- PostGIS: 셀러-고객 거리 계산 (공간 쿼리)

## Q&A 준비

### Q1: "왜 Event Sourcing을 썼나요?"
**A**: "과거 100만 건 주문을 '다시 재생'하려면 
모든 상태 변화를 이벤트로 기록해야 했습니다. 
RDB만으로는 특정 시점으로 '되돌리기'가 불가능했습니다."

### Q2: "실제로 효과가 있을까요?"
**A**: "시뮬레이션이지만, 실제 Olist 데이터로 검증했습니다.
상위 10% 셀러가 이미 24시간 출고를 하고 있으므로,
기술적으로 가능함이 증명됐습니다."

### Q3: "가장 어려웠던 점은?"
**A**: "PostGIS로 50km 반경 내 셀러를 찾는 쿼리 최적화였습니다.
처음엔 30초 걸렸는데, GIST 인덱스로 0.2초로 줄였습니다."

### Q4: "이 프로젝트의 핵심 가치는?"
**A**: "기술이 아니라 '문제 정의'입니다.
배송 지연의 근본 원인을 데이터로 찾아낸 것이 가장 중요했습니다."
