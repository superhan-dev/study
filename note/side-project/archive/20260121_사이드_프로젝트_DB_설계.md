# DB 설계

## 1. [DB 설계] 테이블 목록 및 역할 정의

전체 테이블은 성격에 따라 4개의 그룹으로 분류됩니다.

### 1.1. Core Olist Group (원본 데이터 및 주문 흐름)

- 사용 서버: Server A: Command Service (Order Side)
- 책임: 비즈니스 트랜잭션의 원천 데이터(Source of Truth) 생성 및 저장.

Olist에서 제공하는 표준 데이터셋을 담는 테이블. 주문의 라이프사이클을 추적한다.

- olist_orders: 주문의 마스터 정보 및 상태별 타임스탬프 관리.
- olist_order_items: 주문별 상세 상품 리스트 및 판매자 매핑.
- olist_order_payments: 결제 수단 및 금액 정보.
- olist_products: 상품 카테고리, 무게, 부피 등 물류 제약 조건 정보.
- olist_sellers: 판매자 위치 정보 (출발 노드).
- olist_customers: 고객 위치 정보 (도착 노드).
- olist_order_reviews: 고객 만족도 데이터 (CX 지표).
- olist_geolocation: 우편번호 기반 위경도 데이터 (거리 계산용)

### 1.1.2. Inventory Group (지능형 재고 관리)

단순 OMS를 넘어 WMS 기능을 수행하기 위해 새롭게 설계된 테이블.

- olist_inventory: [신규] 상품별 현재 실재고, 예약 재고, 가용 재고 현황 관리.
- olist_inventory_events: [신규] 모든 재고 변동(입고, 예약, 출고, 반품)의 이력(Ledger).
- inventory_reorder_config: [신규] 상품/셀러별 안전 재고(Safety Stock) 및 재발주 시점(Reorder Point) 설정값.

### 1.1.3. Monitoring & Intelligence Group (지연 예측 및 랭킹)

분석 결과(Z-Score 등)를 저장하고 실시간 알림을 트리거하기 위한 테이블.

- seller_performance_stats: [신규] 셀러/카테고리별 과거 평균 처리 시간($\mu$) 및 표준편차($\sigma$) 통계.
- delivery_delay_alerts: [신규] 시스템이 감지한 지연 위험(Warning, Critical) 로그 및 조치 이력.
- seller_rankings: [신규] 배송 속도, 신뢰도, 만족도를 종합한 셀러 등급 데이터.

### 1.1.4. Logistics Group (경로 최적화)

배송 경로 추천 기능을 구현하기 위한 집계 데이터 테이블.

- route_leadtime_stats: [신규] 우편번호(Zip-code) 구간별 실제 소요 시간 통계 및 가중치 정보.

## 2. DDL

### 2.1. Core 서비스 및 마스터 데이터

- 사용 서버: Server A: Command Service (Order Side)
  - 기존 olist data 테이블.

```sql
-- 1.1. 고객 및 판매자 위치 정보
CREATE TABLE IF NOT EXISTS olist_customers (
    customer_id VARCHAR(32) PRIMARY KEY,
    customer_unique_id VARCHAR(32),
    customer_zip_code_prefix INTEGER,
    customer_city VARCHAR(50),
    customer_state CHAR(2)
);

CREATE TABLE IF NOT EXISTS olist_sellers (
    seller_id VARCHAR(32) PRIMARY KEY,
    seller_zip_code_prefix INTEGER,
    seller_city VARCHAR(50),
    seller_state CHAR(2)
);

-- 1.2. 지리 위치 정보 (PostGIS 연산의 핵심)
-- Server C(Query Side)에서는 이 데이터를 기반으로 GEOMETRY 포인트를 생성합니다.
CREATE TABLE IF NOT EXISTS olist_geolocation (
    geolocation_zip_code_prefix INTEGER,
    geolocation_lat DECIMAL(18, 15),
    geolocation_lng DECIMAL(18, 15),
    geolocation_city VARCHAR(50),
    geolocation_state CHAR(2)
);

-- 1.3. 상품 마스터
CREATE TABLE IF NOT EXISTS olist_products (
    product_id VARCHAR(32) PRIMARY KEY,
    product_category_name VARCHAR(50),
    product_weight_g INTEGER,
    product_length_cm INTEGER,
    product_height_cm INTEGER,
    product_width_cm INTEGER
);

-- 1.4. 주문 마스터 (OMS 핵심)
CREATE TABLE IF NOT EXISTS olist_orders (
    order_id VARCHAR(32) PRIMARY KEY,
    customer_id VARCHAR(32) REFERENCES olist_customers(customer_id),
    order_status VARCHAR(20),
    order_purchase_timestamp TIMESTAMP NOT NULL,
    order_approved_at TIMESTAMP,
    order_delivered_carrier_date TIMESTAMP,
    order_delivered_customer_date TIMESTAMP,
    order_estimated_delivery_date TIMESTAMP
);

-- 1.5. 주문 상세 항목
CREATE TABLE IF NOT EXISTS olist_order_items (
    order_id VARCHAR(32) REFERENCES olist_orders(order_id),
    order_item_id INTEGER,
    product_id VARCHAR(32) REFERENCES olist_products(product_id),
    seller_id VARCHAR(32) REFERENCES olist_sellers(seller_id),
    shipping_limit_date TIMESTAMP,
    price DECIMAL(10, 2),
    freight_value DECIMAL(10, 2),
    PRIMARY KEY (order_id, order_item_id)
);

-- 1.6. 결제 정보 (누락분 추가)
CREATE TABLE IF NOT EXISTS olist_order_payments (
    order_id VARCHAR(32) REFERENCES olist_orders(order_id),
    payment_sequential INTEGER,
    payment_type VARCHAR(20),
    payment_installments INTEGER,
    payment_value DECIMAL(10, 2),
    PRIMARY KEY (order_id, payment_sequential)
);

-- 1.7. 고객 리뷰 (CX 및 셀러 랭킹 분석용 - 누락분 추가)
CREATE TABLE IF NOT EXISTS olist_order_reviews (
    review_id VARCHAR(32) PRIMARY KEY,
    order_id VARCHAR(32) REFERENCES olist_orders(order_id),
    review_score INTEGER check (review_score between 1 and 5),
    review_comment_title TEXT,
    review_comment_message TEXT,
    review_creation_date TIMESTAMP,
    review_answer_timestamp TIMESTAMP
);

```

### 2.2. Intelligent Inventory (WMS 확장)

- 사용 서버: Server A: Command Service (Order Side)
  - 실시간 가용 재고 파악과 자동발주를 위한 핵심 테이블.

```sql
-- 2.1. 실시간 재고 현황 테이블
CREATE TABLE IF NOT EXISTS olist_inventory (
    product_id VARCHAR(32),
    seller_id VARCHAR(32),
    current_stock INTEGER DEFAULT 0,      -- 실물 재고
    reserved_stock INTEGER DEFAULT 0,     -- 예약 재고 (결제 승인 후 출고 전)
    safety_stock INTEGER DEFAULT 10,      -- 안전 재고 임계치
    reorder_point INTEGER,                -- 자동 발주 시점
    last_updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (product_id, seller_id),
    FOREIGN KEY (product_id) REFERENCES olist_products(product_id),
    FOREIGN KEY (seller_id) REFERENCES olist_sellers(seller_id)
);

-- 2.2. 재고 변동 이력 (Ledger)
CREATE TABLE IF NOT EXISTS olist_inventory_events (
    event_id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    product_id VARCHAR(32),
    seller_id VARCHAR(32),
    order_id VARCHAR(32),
    event_type VARCHAR(20),               -- RECEIVED, RESERVED, SHIPPED, CANCELED
    quantity INTEGER,
    event_timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    source VARCHAR(20)                    -- 'REPLAY', 'REALTIME'
);

```

### 2.3. Monitoring & Intelligence (지연 예측 및 랭킹)

- 사용 서버 : [Server C] Query Side: 모니터링 및 지능형 데이터
  분석 기반 인사이트를 시스템 액션으로 연결하기 위한 테이블

```sql
-- 3.1. 셀러 퍼포먼스 통계 (Z-Score 계산용)
CREATE TABLE IF NOT EXISTS seller_performance_stats (
    seller_id VARCHAR(32) PRIMARY KEY REFERENCES olist_sellers(seller_id),
    mu_prep_time_hrs DECIMAL(10, 2),      -- 평균 처리 시간 (μ)
    sigma_prep_time_hrs DECIMAL(10, 2),   -- 처리 시간 표준편차 (σ)
    total_orders_analyzed INTEGER,
    last_computed_at TIMESTAMP
);

-- 3.2. 지연 예측 알림 로그
CREATE TABLE IF NOT EXISTS delivery_delay_alerts (
    alert_id SERIAL PRIMARY KEY,
    order_id VARCHAR(32) REFERENCES olist_orders(order_id),
    z_score DECIMAL(5, 2),                -- 지연 심각도 수치
    severity_level VARCHAR(15),           -- NOTICE, WARNING, CRITICAL
    alert_timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_notified BOOLEAN DEFAULT FALSE     -- 셀러/고객 알림 발송 여부
);

-- 3.3. 구간별 배송 리드타임 통계 (경로 추천용)
CREATE TABLE IF NOT EXISTS route_leadtime_stats (
    seller_zip_prefix INTEGER,
    customer_zip_prefix INTEGER,
    avg_transit_time_hrs DECIMAL(10, 2),
    route_reliability_score DECIMAL(5, 2), -- 안정성 점수
    PRIMARY KEY (seller_zip_prefix, customer_zip_prefix)
);

```

### 2.4. 주요 설계 특징 및 최적화 포인트

1. 가용 재고 산출 지원: olist_inventory 테이블에서 `current_stock - reserved_stock` 연산을 통해 실시간 판매 가능 수량을 즉시 계산할 수 있다.

2. 이벤트 기반 추적: olist_inventory_events는 '누가, 언제, 왜' 재고를 건드렸는지 기록하여 데이터 리플레이 시 시점별 재고 복원이 가능하게 합니다.

3. 성능 통계 분리: Z-Score 계산을 위해 매번 대량의 주문 테이블을 조인하지 않도록, 통계값(mu, sigma)을 seller_performance_stats에 별도로 관리하여 실시간 지연 탐지 성능을 높였습니다.

4. 인덱싱 전략:

- olist_orders: order_purchase_timestamp에 인덱스를 생성하여 리플레이 스트리밍 성능 최적화.
- olist_inventory_events: product_id와 event_timestamp 복합 인덱스로 특정 상품의 이력 추적 속도 개선.
